# 📕 错误登记册 · RSI 自我迭代（Lessons Register）

> 机制闭环：**发现 → 登记（下班）→ 修正（当天或次日第一项）→ 验证（上班 · 跑闸门命令）→ 归档（连续 2 次通过）**
> 方法来源：Google SRE 无指责复盘 · 「修复必须配回归测试」工程文化 · Darwin Gödel Machine / SICA 的「评估驱动自我改进」· self-learning-skills 的「黄金路径 + 死路捕获」
> 硬规则：① 每条必须带「预防闸门」并注册进 `pipeline/tools/rsi_check.sh` —— 无闸门 = 修正未完成；② 验证只在「上班打卡」执行；③ 同根因二次触发 → 强制升级为流程条款；④ 根因 ≥2 层（现象→直接→系统）；⑤ 死路与黄金路径同等重要——都记；⑥ 机制自身缺陷也登记（RSI 的 RSI）

## L-001（演示条目 · 脱敏自真实实践）· 执行通道未锁定，同根因两度触发目标服务风控【🟡】
- **日期**：2026-XX-XX
- **严重级**：S2
- **检测来源**：工具自动拦截（非人工发现）
- **症状**：自动化任务被目标服务环境风控拦截，报错提示当前执行通道异常
- **根因（3层）**：①现象=请求被拦截；②直接=任务走了默认可降级通道，静默落到高风险通道；③系统=执行前没有「通道锁定」的强制闸门（知识写在记忆里，闸门不在流程里）
- **修正**：①执行前置检查条款（通道锁定 · 禁高风险通道 · 不降级）；②高风险通道须先「定证」再启用；③建立登记册 + 闸门自动化
- **预防闸门**：前置检查条款在岗（已注册为 rsi_check.sh 检查项）
- **🚫 死路（不要重走）**：默认参数静默降级；未经定证直接重试
- **复发计数**：1（累计 2 次同根因）
- **验证记录**：待首次验证（下一个上班打卡）
